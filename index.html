視点をどこに置くか

杉浦康平「右往左往する富士山の地図」から考える、データの描き方

矢崎裕一

グラフィックデザイナーの杉浦康平氏に、「右往左往する富士山の地図」というダイアグラムがあります。東名高速道路を走るとき、富士山の見える方向と距離がどう変わるかを描いた図です。私は講演や講義で、この図をよく引き合いに出してきました。視点をどこに置くかで、描かれるものがまったく変わることを、はっきり見せてくれるからです。

このページでは、そのアイデアを公開データで計算し直した図を動かしながら、データを人に伝えるときの視点の置き方を考えます。図は原図を再現したものではありません。

まず、予想してください

東京から西宮まで、東名・名神高速道路を走ります。この道路を、まっすぐな一本の線に伸ばします。道路上の各地点から富士山への方向と距離は、そのまま変えません。すると富士山は、まっすぐな線に対してどこに現れるでしょうか。

選んだら、下の図のスイッチを入れて確かめてください。

止まっているものを入れ替えると、動くものが入れ替わる

地図では、富士山は一点に止まっていて、曲がりくねっているのは道路です。まっすぐにした図では逆に、道路が止まっていて、富士山が動きます。描いているデータはどちらも同じで、各地点から富士山への方向と距離です。

違うのは、何を「動かないもの」として描いたかです。地図は、地面を動かないものとして描いています。だから山は動かず、その上を通る道路が曲がります。まっすぐにした図は、車の向きを動かないものとして描いています。車はいつも図の左を向いています。道が右へ曲がると、車から見た富士山はそのぶん左へずれるので、図の上でも富士山の位置が変わります。

運転席に座ってみる

まっすぐにした図は、運転席からの眺めとも言えます。車がどちらを向いていても、運転する人はいつも正面を見ているからです。そこで、同じ計算を運転席の眺めにしました。「走る」を押すか、スライダーを動かしてください。

走らせてみると、運転席の眺めの弱点も分かります。

  • 見えるのは「いま」だけです。全線を通して富士山がどう動いたかは、走り終えても頭に残りません。そのため、方向の推移をまとめた図を下に足す必要がありました。
  • 誰の席に座らせるかで、絵が変わります。下りでは、富士インターチェンジを過ぎると富士山は後ろへ回り、その先はルームミラーの中か斜め後ろです。上りに切り替えると、正面に見える時間がずっと長くなります。
  • 自分の見ている景色がふつうなのか、例外なのかは分かりません。比べるには、全体を見渡す図が要ります。

4つの図を並べる

ここまでの図は、2つの問いで整理できます。何を基準にして描くか。全体を見渡すのか、その場から見るのか。組み合わせは4つあるので、まだ出てきていない1つを足しました。展望台にある方位盤のように、その場に立って周りを見るけれど、東西南北は地面に合わせたままの図です。スライダーを動かすと、同じ地点を4つの図で同時に追えます。

地面を基準にする
走る人を基準にする
全体を見渡す
その場から見る

左下の方位盤を見てください。富士山は西から北を回って東へ、ゆっくり移るだけで、大きく行き来することはありません。その代わりに、車の向きを示す印のほうが左右に振れます。運転席と同じ「その場からの眺め」なのに、富士山は右往左往しないのです。右往左往の原因は、場所が変わることではなく、車の向きが変わることだと分かります。

そして、右往左往が一目で分かるのは、右上の図だけです。地図では富士山は動きません。運転席では、動きは見えても全体が残りません。杉浦氏の図は運転席からの眺めではなく、走る人を基準に描いたものを、全体が見渡せる形にしています。

保ったものと、捨てたもの

基準を変えるとは、何を保ち、何を捨てるかを決めることです。まっすぐにした図は、富士山までの距離と、道路に対する角度を保ちました。その代わりに、方角と、海岸線や地形との位置関係を捨てています。下の表は、上のスライダーの地点での値です。

地図ではないデータで、同じことをする

同じことは、地図ではないデータにも言えます。鉄道の時刻表で試します。駅を選び、時刻を動かしてください。

  • 各駅停車
  • 快速（さくら台とかわべは通過）
  • いまの時刻、自分の駅

説明のために作った架空の路線とダイヤです。みなと発やまのうえ行きの、朝7時から9時までを描いています。

ダイヤグラムは、運行する側の図です。すべての列車と駅が一望できます。けれどもホームに立つ人は、自分の駅の線と、いまの時刻の線が交わるところを、自分で探さなければなりません。

発車標は、ホームに立つ人の図です。原点は「いま、この駅」。単位は時刻ではなく「あと何分」です。ただし運転席と同じで、見えるのは「いま」だけです。

待ち時間の図は、ホームに立つ人を基準にしたまま、朝の2時間を見渡したものです。何時にホームへ着くと長く待つのかが、一目で分かります。駅を「さくら台」に変えると、快速が止まらないぶん山が高くなります。

4つめの組み合わせ、つまり運行する側を基準にその場から見る図もあります。運転士が持つ、1本の列車だけの時刻表がそれです。ここでは描いていません。

ここでも、保ったものと捨てたものがあります。保ったのは、自分の駅を出る列車の時刻です。捨てたのは、ほかの駅のことと、列車どうしの関係です。

自分のデータで描き直すとき

富士山と時刻表でやったことを、手順にするとこうなります。

  1. 読み手は誰か。どの席に座らせるか。下りと上り、中央駅とさくら台駅で、絵は変わります。席は描く人が決めることになります。
  2. 原点をどこに置くか。読み手がいまいる場所、いまの時刻、読み手自身の値。
  3. 軸と単位を何にするか。東西南北ではなく前後左右。時刻ではなく「あと何分」。
  4. 何を保ち、何を捨てるか。保つものを決めないと、描き直した図は元のデータと別のものになります。
  5. 描き直したものを、見渡せる形にする。「いま」だけを見せて終わらせない。

俯瞰か、運転席か

地図は俯瞰の視点で、全体を管理する側、いわば行政の視点です。運転席は主観の視点です。一般の人にデータを伝えようとするなら、俯瞰よりも運転席の視点で描くべきではないか。私はそう考えてきました。

ただ、運転席に座らせるだけでは「いま」しか見えません。自分の景色がふつうなのかどうかも分かりません。杉浦氏の図が教えてくれるのは、その先です。走る人を基準に描き直し、それを全体が見渡せる形にする。入口は運転席で、出口は俯瞰です。

座標系とは、何を基準にして描くか、ということです。

読み手の座標系で描き直してから、俯瞰させる。

道路をまっすぐにして富士山のほうを動かすアイデアは、杉浦康平氏のダイアグラム「右往左往する富士山の地図」によります。このページの図は、公開データから計算し直した習作です。地点の取り方や道路の精度が原図と違うため、形は一致しません。

道路・海岸線・湖は Natural Earth（1:1000万）の公開データです。線形は簡略化されていて、実際の道のりより短く、位置に数kmのずれがあります。遠い地点では実際には富士山は見えません。方向と距離は地図上の計算です。計算の詳細とソースコードは GitHub のリポジトリにあります。
